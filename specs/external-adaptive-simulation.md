# External Adaptive Simulation Interface

Status: implemented architecture extension  
Schema family: `interceptor.dev/v1alpha1`  
Date: 2026-09-02

## 1. Purpose

This document specifies Interceptor Sandbox enhancements needed for reliable
adaptive attack simulation. The interfaces are producer-neutral:

- Operator Sandbox can use them to execute an AEF ScenarioBundle;
- PromptFoo or another harness can use them without AEF or Operator;
- AEF can consume capability and post-run evidence resources without becoming
  an Interceptor runtime dependency.

Interceptor remains a simple, independently useful open-source execution and
evidence environment. It does not generate payloads, run an attack-planning
loop, or interpret AEF technique objects.

The IDs are retained for traceability even though `AEF` in an ID no longer
means the feature is proprietary or AEF-specific.

## 2. Updated interaction model

```text
planning:
Interceptor CapabilityManifest -> AEF or another planner

execution:
external engine -> producer-neutral AttemptContext -> Interceptor operation
                <- target response + permitted ObservationView

post-run proprietary product:
Operator CampaignExecutionBundle + Interceptor EvidenceBundle(s) -> AEF assessment
```

The external attack engine crafts the concrete payload. AEF may provide optional
scenario and technique provenance, but Interceptor validates only generic
identity, content, operation, policy, and session bindings.

During ordinary execution, the harness does not receive all information that
Interceptor records. This asymmetry is intentional. Protected evidence is
exported through a trusted post-run path and allows AEF to compare the attacker's
view with execution truth without giving the engine unfair live knowledge.

## 4. INT-AEF-AD-001 — attempt context and ancestry

### 4.1 Problem

Adaptive engines create, refine, branch, and stage attempts dynamically. Static
injection IDs alone cannot explain which generated artifact caused an
Interceptor event or how one attempt evolved from another.

### 4.2 AttemptContext

Register one immutable context before arming or executing its payload:

```json
{
  "api_version": "interceptor.dev/attempt-context/v1alpha1",
  "campaign_id": "campaign-01",
  "thread_id": "thread-01",
  "attempt_id": "attempt-0003",
  "parent_attempt_id": "attempt-0002",
  "generation": 3,
  "attempt_index": 17,
  "payload": {
    "digest": "sha256:...",
    "size_bytes": 97,
    "media_type": "application/json"
  },
  "generator": {
    "kind": "adaptive-engine",
    "release_digest": "sha256:..."
  },
  "strategy_provenance_ref": "sha256:...",
  "feedback_profile": "black-box",
  "created_at": "2026-08-31T20:00:00Z"
}
```

`strategy_provenance_ref` is optional and opaque to Interceptor. It may point to
AEF scenario/action/recipe provenance, a PromptFoo test case, or another
producer's metadata. Interceptor MUST NOT require or dereference it.

Registration requirements:

- campaign, thread, attempt, and parent relationships are bounded and stable;
- attempt IDs are unique within the session and cannot be overwritten;
- a parent must already exist in the same campaign and permitted thread graph;
- generation and attempt index are monotonic according to the session policy;
- payload descriptor matches a registered, verified artifact;
- the selected feedback profile matches immutable session policy;
- metadata cannot change routing, authorization, visibility, or safety policy.

### 4.3 Propagation

All injections, application turns, normalized events, provider-boundary
deliveries, oracle results, and artifact lifecycle records caused by an attempt
carry `attempt_id` and payload digest when known. Derived internal work preserves
causal ancestry rather than relying on timing.

Dynamic registration is bounded by attempt, artifact, byte, and rate limits.

## 5. INT-AEF-AD-002 — feedback visibility and ObservationView

### 5.1 Visibility classes

Interceptor classifies recorded facts as:

- `target_visible` — natural application output a real target user sees;
- `harness_visible` — normalized operational fact permitted to the harness;
- `operator_only` — trusted control-plane diagnostic or lifecycle fact;
- `protected` — raw evidence, oracle internals, fixture values, canaries,
  provider-boundary details, or sensitive state.

Classification occurs before serialization. A protected field is omitted, not
returned with a label that asks the caller to ignore it.

### 5.2 FeedbackProfile

Every session selects one immutable profile, initially:

- `black-box` — target-visible output and minimum operation status;
- `diagnostic` — black-box plus allowlisted coarse normalized observations;
- `oracle-assisted` — explicit research mode exposing selected oracle outcomes,
  never raw secrets or unrestricted events.

The environment declares which profiles it supports. An execution lease may narrow but
cannot broaden the active profile.

### 5.3 ObservationView

```json
{
  "api_version": "interceptor.dev/observation-view/v1alpha1",
  "session_id": "session-01",
  "attempt_id": "attempt-0003",
  "feedback_profile": "black-box",
  "operation": {
    "state": "SUCCEEDED",
    "receipt_id": "receipt-01"
  },
  "target_output": {
    "artifact_digest": "sha256:...",
    "media_type": "application/json"
  },
  "observations": [],
  "session_revision": 43
}
```

Outputs are bounded and content bodies use authorized artifact reads when too
large for the response. Absence of an observation is not evidence that an
effect did not occur.

## 6. INT-AEF-AD-003 — capability manifest

Interceptor exports a deterministic, secret-free `CapabilityManifest` bound to
the sealed Environment and Application digests. It includes:

- manifest and Interceptor schema/release versions;
- target/application identity and supported feedback profiles;
- typed application and Cross-VM operations;
- injection surfaces, placements, modes, selectors, carriers, and limits;
- per-target injection surfaces, creatable state collections, logical
  file-injection namespaces and their ceilings;
- managed services, native MCP servers/tools, identities, static/dynamic
  synthetic attacker services, and stateful fixtures by stable metadata ID;
- observation kinds and oracle types;
- native model-proxy codecs, host provider-adapter kinds, non-secret
  authentication-mode classes, model/deployment constraints, and feature
  flags;
- snapshot/checkpoint support;
- closed DNS policy/query ceilings and HTTP/HTTPS front-door/TLS trust
  capabilities, without private listener or certificate material;
- attempt, invocation, artifact, concurrency, and size limits.

It excludes credentials, prompt bodies, fixture bodies, hidden canary values,
raw host/container paths, private network details, evidence, and operator-only
configuration.

The same sealed inputs produce the same canonical manifest digest. An execution
lease and any AEF ScenarioBundle bind that exact digest. A changed manifest
requires revalidation and, for AEF plans, a new ScenarioBundle.

## 7. INT-AEF-AD-004 — attempt-indexed evidence export

After live harness authority closes, a trusted operator may request an
immutable `EvidenceBundle`:

```json
{
  "api_version": "interceptor.dev/evidence-bundle/v1alpha1",
  "kind": "EvidenceBundle",
  "campaign_id": "campaign-01",
  "session_id": "session-01",
  "environment_digest": "sha256:...",
  "application_digest": "sha256:...",
  "capability_manifest_digest": "sha256:...",
  "interceptor_release_digest": "sha256:...",
  "feedback_profile": "black-box",
  "completeness": {
    "state": "complete",
    "start_sequence": 1,
    "end_sequence": 902,
    "truncated": false
  },
  "attempts": [],
  "snapshots": [],
  "restores": [],
  "artifact_refs": [],
  "oracles": [],
  "injections": [],
  "coverage_gaps": [],
  "created_at": "2026-08-31T21:00:00Z"
}
```

The bundle indexes authoritative events, injection application, service/tool
results, state mutations, provider-boundary delivery, oracle results, and
causality by attempt and payload digest. Large event sets and bodies are
content-addressed artifacts.

The combined post-run record includes operation and idempotency IDs, request
origin, accepted/completed timestamps, revision effects, and ambiguity
reconciliation from Operator, plus Interceptor's authoritative snapshot ID,
digest, canonical committed size, parent snapshot, sealed environment,
application, capability and release bindings, and result. Restore records also
identify the source and resulting session lineage. Snapshot bodies are not
included in an ordinary EvidenceBundle unless an export policy explicitly
lists them as protected artifacts.

Export requires trusted host authority unavailable to the guest execution lease. The
current local interface writes a deterministic portable tar stream after
integrity verification and includes explicit completeness/truncation markers.
An orderly shutdown persists the final protected evaluation; if abnormal
termination prevents that step, export retains the verified raw record and
marks the bundle partial. Repeating an export of unchanged sealed evidence
yields the same EvidenceBundle digest.

AEF is an important downstream consumer but not the only permitted consumer.
Operator may relay the verified bundle in its FinalSubmission; Interceptor does
not call AEF directly.

## 8. INT-AEF-AD-005 — canonical payload artifact identity

The payload flow is:

1. An external engine generates concrete bytes.
2. Operator or another harness computes a declared digest and registers the
   artifact with Interceptor.
3. Interceptor streams or accepts the bounded body, verifies size, media type,
   canonicalization rule, and digest, then commits it immutably.
4. The producer registers an AttemptContext referring to that digest.
5. An injection or application operation refers to the attempt and digest.
6. Interceptor records the same verified identity through application,
   consumption, delivery, event, and evidence records.
7. Post-run consumers join Operator execution and Interceptor evidence using
   attempt ID plus payload digest.

Example descriptor:

```json
{
  "digest": "sha256:...",
  "size_bytes": 97,
  "media_type": "application/json",
  "canonicalization": "jcs-v1"
}
```

For structured payloads, the contract explicitly chooses whether the digest is
over raw bytes or a versioned canonical representation. It never silently
parses and reserializes. Non-JSON bodies use raw-byte digests. Digest, size,
canonicalization, or media-type mismatch fails before use.

This identity does not imply AEF generated the payload. The artifact may come
from Operator's engine, PromptFoo, a human-authored harness, or another tool.
Normal ObservationView returns the digest, not protected payload content.

## 9. INT-AEF-AD-006 — managed HTTP response injection

**Implementation status:** supported. Managed services expose an
attempt-attributed rewrite point after a successful handler response and before
the application consumes it.

Add `service_response` / `simulation` with this order:

1. authorize the real request;
2. execute the real fixture or stateful handler;
3. construct a normalized response candidate;
4. match service, route, ordinal, and bounded request predicates;
5. apply one typed operation—`replace`, `prepend_text`, `append_text`, or
   `merge_object`—at a JSON Pointer or UTF-8 text body;
6. record original and resulting digests plus attempt/injection identity;
7. return the modified response to the application;
8. independently record any later provider-boundary delivery.

The surface cannot change authorization decisions, identity, destination,
status, or security-sensitive headers. An authorization failure provides no
injectable response candidate. Exact method/path, bounded query/header/body
predicates, and per-definition journaled ordinals make adaptive targeting
reliable after setup traffic. A Blueprint-enabled dynamic attacker HTTP service
uses the same body-only surface after capture; a static sink rejects arming.

## 10. INT-AEF-AD-007 — native MCP result injection

**Implementation status:** supported. `mcp_tool_result` is distinct from
`model_tool_result` and operates between successful native MCP execution and
application consumption.

Add `mcp_tool_result` / `simulation` after native MCP authorization and actual
tool execution. Selectors use stable server ID, tool name, call ordinal, and
bounded scalar argument predicates. Placements and mutation operations use the
same restricted forms as managed HTTP response injection.

Evidence records real-result digest, rewritten-result digest, injection ID,
attempt ID, MCP server/tool identity, and later provider delivery when present.
The manifest reports `mcp_tool_result` and `model_tool_result` as distinct
surfaces so planners and reports make accurate fidelity claims.

### 10.1 Dynamic source completeness

The sealed Blueprint describes where adaptive payloads may be placed; it does
not contain those payloads. `environment_state` may create a missing service
record only in an explicitly opted collection with a positive ceiling and a
sealed stateful HTTP/MCP create contract that validates the complete object. A
missing file may be created only through a named logical injection namespace
with explicit permission and file-count and byte ceilings. Absolute file paths
remain update-only.

A Blueprint MAY declare multiple attacker HTTP services. Static responses are
capture-only exfiltration sinks. Dynamic responses reuse `service_response`
after capture and provide bounded request/response C2 simulation without adding
a generic proxy or unrestricted tasking channel.

Local command execution is not a syscall-interposition surface. `curl` and
similar clients receive injected bytes when they call a declared injectable
HTTP service; command output later represented as a client tool result is
covered by `model_tool_result`. The manifest MUST NOT claim interception of
arbitrary descendant stdout or undeclared localhost communication.

## 11. INT-AEF-AD-008 — checkpoint fork convenience

**Implementation status:** deliberately deferred. Compose the existing
Operator-controlled snapshot and trusted host restore operations unless
measurements demonstrate that an additional atomic primitive is necessary.

The baseline Cross-VM interface exposes narrow Operator-controlled live
`snapshot.create`; restore remains an existing host control-plane operation
because it creates a fresh Interceptor session. Add an optional atomic
convenience operation that quiesces and checkpoints a
session, creates named children, attaches distinct thread contexts, preserves a
common parent checkpoint, and applies the same snapshot limits and safety
checks.

The fork convenience remains deliberately marginal. A trusted external
orchestrator can implement the same sequence using the narrow primitives. The
attack-engine process never receives an Interceptor administrative credential
or unrestricted restore authority. It may make a typed request to Operator,
but Operator decides whether and when to issue the actual Interceptor mutation.

## 12. INT-AEF-AD-009 — typed event-match oracle

Add a bounded deterministic `event_match` oracle for effects already represented
as normalized events. Filters may include exact channel, layer, kind,
attempt/injection identity, and provenance values. Top-level semantic fields,
including normalized operations, use bounded scalar predicates:

- `equals`
- `contains`
- `exists`
- `one_of`

Do not support scripts, regular expressions, arbitrary JSONPath, callbacks, or
user-selected code. Results include bounded count, first matching event sequence
and digest, visibility, and causality state. Causality is confirmed only through
explicit attempt/injection provenance, never time proximity alone.

Raw oracle details remain protected unless an immutable oracle-assisted profile
expressly exposes a normalized result.

## 13. INT-AEF-AD-010 — Cross-VM harness interface

### 13.1 Boundary

Loopback cooperative-control URLs are local conveniences and not a production
authorization boundary. Production Operator engines run in a separate microVM
and receive no Docker socket, Interceptor data root, private Unix socket, host
path, provider credential, generic network tunnel, arbitrary proxy, shell, raw
event stream, signing key, canary, or protected evidence.

```text
operator guest          trusted Operator Runtime       Interceptor gateway
attack engine   <---->  typed policy broker    <---->  typed execution API
```

AEF is not a live caller. It supplies the ScenarioBundle to the trusted
Operator Runtime before execution and receives finalized bundles afterward.

### 13.2 Integration authentication and ExecutionLease

The gateway runs for one already-running Interceptor session. It does not
create sessions or select environments. The trusted Runtime first authenticates
with a shared integration bearer token and requests an immutable, short-lived
ExecutionLease:

```json
{
  "api_version": "interceptor.dev/execution-lease-request/v1alpha1",
  "idempotency_key": "issue-campaign-01-revision-01",
  "operator_vm_instance_id": "opvm-random-per-boot",
  "campaign_id": "campaign-01",
  "session_id": "session-approved",
  "scenario_bundle_digest": "sha256:...",
  "capability_manifest_digest": "sha256:...",
  "environment_digest": "sha256:...",
  "application_digest": "sha256:...",
  "feedback_profile": "black-box",
  "allowed_operations": [
    "session.status",
    "capabilities.read",
    "artifact.register",
    "artifact.read",
    "attempt.register",
    "injection.arm",
    "injection.delete",
    "application.invoke",
    "observation.read",
    "snapshot.create",
    "session.stop"
  ],
  "limits": {
    "maximum_attempts": 120,
    "maximum_concurrent_invocations": 1,
    "maximum_artifact_bytes": 1073741824,
    "maximum_wall_seconds": 3600,
    "maximum_snapshot_creations": 8,
    "maximum_cumulative_snapshot_bytes": 4294967296
  },
  "expires_at": "2026-08-31T21:00:00Z"
}
```

`POST /v1/execution-leases` requires `Authorization: Bearer
<integration-token>`. The integration token is mapped by configuration to one
bounded principal and is used only for lease issuance, introspection, and
revocation. Production controllers resolve it through HostCredentialRef from
AWS Secrets Manager, Azure Key Vault, Google Cloud Secret Manager, or
HashiCorp Vault. Environment token input is a development-only compatibility
source and production mode rejects it. The token is never accepted as a CLI
argument, exposed to the sandbox guest, or persisted in evidence.

The gateway returns an `interceptor.dev/execution-lease/v1alpha1` record and a
random opaque bearer `access_token`. The token is returned only in the
idempotent issuance response. The gateway stores its digest for ordinary
lookup and keeps lease state in memory for the lifetime of the per-session
process. `GET /v1/execution-leases/{lease_id}` returns public lease state and
usage but never the token. `DELETE` revokes it immediately. Both administrative
operations require the integration token; `POST /v1/cross-vm` requires the
distinct lease token.

```json
{
  "lease": {
    "api_version": "interceptor.dev/execution-lease/v1alpha1",
    "lease_id": "lease-random-opaque-identifier",
    "principal": "operator-runtime-01",
    "operator_vm_instance_id": "opvm-random-per-boot",
    "campaign_id": "campaign-01",
    "session_id": "session-approved",
    "scenario_bundle_digest": "sha256:...",
    "capability_manifest_digest": "sha256:...",
    "environment_digest": "sha256:...",
    "application_digest": "sha256:...",
    "feedback_profile": "black-box",
    "allowed_operations": ["session.status", "application.invoke"],
    "limits": {"maximum_concurrent_invocations": 1},
    "issued_at": "2026-08-31T20:00:00Z",
    "expires_at": "2026-08-31T21:00:00Z",
    "status": "active"
  },
  "access_token": "opaque-secret-returned-only-at-issuance",
  "token_type": "Bearer"
}
```

IDs, timestamps, arrays, and limits are bounded. Session, environment,
application, manifest, VM instance, and feedback profile must match live state.
Unknown, expired, revoked, stale, or mismatched leases fail closed. An issuance
idempotency key repeated with the exact body returns the same response; reuse
with different content fails.

Zero or omitted request limit fields inherit the gateway's session-derived
ceiling. Nonzero values above the ceiling or implementation defensive maximum
are rejected rather than truncated. Native Interceptor limits still apply.

The ScenarioBundle digest is a correlation and narrowing claim; it is optional
for non-AEF producers. It cannot broaden Interceptor policy.

Snapshot fields are optional ceilings and apply only when `snapshot.create` is
also present in `allowed_operations`. They never disable Interceptor's
configured hard capacity limits. An accepted create mutation consumes its
operation count even if it later fails. Only a successfully committed snapshot
consumes canonical snapshot bytes; deleting it does not refund cumulative
bytes. Operator supplies the remaining campaign allowance when requesting each
fresh lease; Interceptor additionally enforces its native per-session limits.

### 13.3 Request and idempotency

```json
{
  "api_version": "interceptor.dev/cross-vm-request/v1alpha1",
  "request_id": "req-unique",
  "idempotency_key": "idem-unique",
  "lease_id": "lease-opaque-identifier",
  "operation": "application.invoke",
  "session_id": "session-approved",
  "operator_vm_instance_id": "opvm-random-per-boot",
  "expected_session_revision": 42,
  "attempt_id": "attempt-0003",
  "attempt_context_digest": "sha256:...",
  "body_digest": "sha256:...",
  "deadline": "2026-08-31T20:02:00Z"
}
```

The gateway resolves the bearer token to its server-side lease, validates the
body against the operation schema, verifies its digest, and atomically checks
expected session revision for mutations. The request `lease_id` must match that
resolved lease.

Idempotency keys are scoped to lease, session, operation, and body digest. A
concurrent duplicate receives `operation_in_progress` and never executes the
mutation twice; reuse with different content fails. Completed/unknown receipts
and in-flight keys are bounded. An ambiguous mutation timeout is `UNKNOWN`, not
an automatic retry. The caller reconciles by operation status or stops for
trusted review.

### 13.4 Initial operation surface

| Operation | Purpose |
|---|---|
| `session.status` | Bounded lifecycle, revision, and remaining limits. |
| `operation.status` | Mutation receipt lookup by bound idempotency key. |
| `capabilities.read` | Secret-free manifest for the bound environment. |
| `artifact.register` | Stream and commit one bounded content-addressed artifact. |
| `artifact.read` | Read one exact registered artifact when the lease explicitly permits content access. |
| `attempt.register` | Register immutable producer-neutral AttemptContext. |
| `injection.arm` | Arm a declared injection for that attempt and artifact. |
| `injection.delete` | Remove one exact injection by ID. |
| `application.invoke` | Invoke one declared application operation. |
| `observation.read` | Return the permitted ObservationView. |
| `snapshot.create` | Operator-controlled quiesce and content-addressed snapshot creation. |
| `session.stop` | Request orderly stop. |

Evidence export, raw evaluation, session creation/deletion, environment sealing,
provider selection, image construction, snapshot deletion/export, and
unrestricted or cross-campaign restoration are host/control-plane operations
under separate credentials.

Snapshot mutations require expected session revision, operation idempotency,
campaign/session and sealed environment/application/capability/release
bindings, parent lineage where applicable, and a bounded reason. The response
is a bounded receipt and does not expose snapshot bytes or protected inventory
to the guest.

Restore is never added to a live ExecutionLease. Operator first revokes the current
lease and stops its guest, then invokes Interceptor's authenticated host restore
operation with an exact permitted source session and checkpoint. Interceptor
verifies the checkpoint and sealed inputs and creates a fresh session with
`restored_from` ancestry. Operator validates that result and requests a fresh
ExecutionLease for a fresh MicroVM revision. Failed restore leaves the source session
and checkpoint unchanged.

The gateway constructs private local requests from typed values. It never
forwards guest-supplied URLs, paths, headers, CLI arguments, or bridge commands.

### 13.5 Transport and availability

The implemented network profile is a private HTTP backend behind an
enterprise-managed TLS load balancer or private reverse proxy. The load
balancer owns certificates and HTTPS; direct exposure of the HTTP listener to
an untrusted network is nonconformant. Bearer authentication is independent of
network topology, so Operator and Interceptor may run on different hosts.
Integrity in transit is supplied by the front-end TLS path; application-level
authorization, idempotency, bounded frames, deadlines, and rate limits remain
enforced by the gateway.

Revocation, expiry, guest termination, or session stop immediately prevents new
operations. Interceptor outage yields bounded failure; it does not authorize a
fallback path around the gateway.

### 13.6 Post-run export boundary

After Operator revokes the live ExecutionLease and stops the guest, the trusted host
may use separate host export authority to request the EvidenceBundle for that session.
The live lease can never be upgraded in place. Evidence bytes return only to
the trusted host, which verifies and binds every campaign session's bundle into
its AEF FinalSubmission.

## 14. INT-AEF-AD-011 — extended native model providers

**Implementation status:** supported alongside OpenAI Chat Completions, OpenAI
Responses, Bedrock Converse, and LiteLLM. The native, like-for-like providers
are:

| Provider adapter | Application codec and route | Host behavior |
|---|---|---|
| `anthropic-messages` | `anthropic_messages`, `POST /v1/messages` | Fixed-origin Anthropic Messages request with host API key or configured workload token and pinned API version. |
| `gemini-api` | `google_generate_content`, Gemini `models/{model}:generateContent` | Fixed Gemini Developer API origin with host `x-goog-api-key`. |
| `vertex-gemini` | `google_generate_content`, Vertex publisher-model `generateContent` | Fixed Google Cloud project, location, publisher, API version, and host ADC/workload identity. |
| `azure-openai` | Existing `openai_chat_completions` and `openai_responses` codecs under `/openai/v1` | Fixed Azure OpenAI/Foundry resource with host API key or Entra workload identity. |

The local application proxy accepts the native route needed by its SDK, checks
an exact model or Azure deployment allowlist, and sends the unchanged native
semantic shape to the compatible host adapter. It does not translate Anthropic,
Google, OpenAI, or Bedrock conversations into another provider's protocol.
Incompatible codec/provider pairs fail explicitly.

The application may receive declared synthetic SDK credentials that are valid
only for Interceptor's reserved `model-proxy`. The proxy ignores and strips
them. Real API keys, cloud credentials, acquired OAuth tokens, Anthropic API
versions, Google project/location, Azure resource origins, and provider routing
remain host configuration and never enter the Blueprint, container, snapshot,
evidence body, or exported artifact.

The first slice supports non-streaming text, system instructions, bounded
generation parameters, structured text/JSON output, and client-side function
declarations, calls, and results. Client functions remain application-executed;
the model provider only returns structured data. Reject streaming, embeddings,
image/audio/video/document blocks, file or remote-URL references, cached or
provider-stored conversation dependencies, background/batch operations,
Anthropic server tools, Gemini grounding or code execution, and Azure/OpenAI
hosted tools.

Provider configuration and validation requirements are:

- fixed HTTP origins reject user information, fragments, caller-supplied query
  strings, and cross-origin redirects;
- Anthropic pins the required API version and rejects undeclared beta headers;
- Gemini constructs its model path from an exact allowlist and accepts no guest
  destination;
- Vertex fixes project, location, publisher `google`, API origin, and version;
- Azure uses the configured `/openai/v1` resource origin and treats `model` as
  an exact deployment allowlist value; and
- all adapters retain existing body, timeout, concurrency, session, and
  provider-error bounds.

CapabilityManifest reports provider kinds, compatible codecs, authentication
mode classes without credential identifiers, model-ID constraints, and feature
flags for text, client functions, structured output, streaming, embeddings,
multimodal content, provider-hosted tools, and provider-stored state.

Evidence records application codec, selected host adapter, exact model or
deployment, pinned non-secret endpoint/API-version metadata, final injected
application request, canonical provider request and response digests,
normalized usage, latency, finish/safety status, bounded provider error, and
injection lineage. Authentication headers, credentials, access tokens, signed
cloud requests, and synthetic credential values are excluded.

## 15. INT-AEF-AD-012 — host secret-store credential resolution

**Implementation status:** supported. A shared host credential resolver covers
AWS Secrets Manager, Azure Key Vault, Google Cloud Secret Manager, and
HashiCorp Vault KV v2. Direct workload identity remains available for Bedrock,
Vertex Gemini, and Azure OpenAI.

Add one host-only credential resolver used by model-provider adapters and any
future trusted controller integration that requires an API key or client
secret. Provider adapters consume a resolved bounded value; they do not each
implement a secret-store client. Workload-identity model authentication such as
Bedrock roles, Vertex identity, or Azure managed identity remains direct and
does not create a needless stored secret.

Schema: `interceptor.dev/host-credential-ref/v1alpha1`

Store profile schema: `interceptor.dev/secret-store-profile/v1alpha1`. It binds
a stable profile ID to exactly one backend kind, production authentication
mode, cloud/region or Vault origin and TLS policy, allowed locator prefixes,
request timeouts, value-size ceiling, and cache-TTL ceiling. It contains no
secret value or static cloud access credential.

```json
{
  "api_version": "interceptor.dev/host-credential-ref/v1alpha1",
  "kind": "HostCredentialRef",
  "credential_id": "target-openai-key",
  "store_profile_id": "production-gcp-secrets",
  "locator": {
    "backend_kind": "gcp-secret-manager",
    "project": "security-simulation-prod",
    "secret": "interceptor-openai",
    "version": "latest"
  },
  "value": {
    "format": "json-string-field",
    "field": "api_key"
  },
  "cache_ttl_seconds": 300
}
```

`HostCredentialRef` and its `SecretStoreProfile` are permission-restricted host
controller configuration. Environment Blueprints, Cross-VM requests, execution
leases, applications, and harnesses refer to neither a store nor a locator. A
reviewed model-provider profile may refer only to the stable `credential_id`.
Untrusted input cannot replace the backend, secret name, version, JSON field,
endpoint, trust root, project, vault, region, namespace, or authentication mode.

The initial backend union is:

| `backend_kind` | Read operation and strict locator | Production bootstrap authentication |
|---|---|---|
| `aws-secrets-manager` | `GetSecretValue` for one exact secret ARN or name, region, and optional version ID or stage | EC2 instance profile, ECS task role, or EKS workload identity through an AWS SDK credential provider constrained by deployment policy |
| `azure-key-vault` | `GetSecret` for one exact HTTPS vault origin, secret name, and optional version | Azure managed identity or workload identity with interactive and static-client-secret fallbacks disabled |
| `gcp-secret-manager` | `AccessSecretVersion` for one exact project, secret, and numeric version or reviewed alias | Compute/GKE attached service account or Workload Identity Federation through constrained application-default credentials |
| `hashicorp-vault` | Read one exact KV v2 namespace, mount, path, version, and field from a fixed HTTPS origin | Vault Agent or Vault Proxy owns environment-appropriate auto-auth and renewal; Interceptor uses a protected token sink or fixed local authenticated proxy |

Cloud stores use official SDK endpoint resolution for the configured cloud and
region; arbitrary endpoint overrides are rejected in production. Private
endpoints use trusted DNS and network policy. Vault profiles pin the exact
origin, namespace, TLS roots, and allowed KV mount/path prefixes. Production
profiles never disable TLS validation.

The resolver exposes read only. It cannot create, update, rotate, list, or
delete secrets, and its bootstrap identity receives only per-secret read
permissions. Cloud stores bootstrap from ambient instance or workload identity,
not static access keys placed in the controller environment. Vault delegates
its many platform authentication methods to the separately administered Agent
or Proxy rather than reimplementing them in Interceptor.

Values are limited to a bounded UTF-8 string or a named top-level JSON string
field. Binary blobs, templates, commands, recursive references, and expression
evaluation are rejected. Provider-returned integrity data, including Google
Secret Manager CRC32C, is verified when available. The controller records only
the credential ID, backend profile ID, opaque provider version, resolution
time, and outcome in protected audit state. It never records the locator,
secret value, authentication material, or an unkeyed secret digest.

Resolve before the first dependent operation and retain the value only in a
bounded host-memory cache. Invalidate it at its configured TTL, on explicit
administrative reload, or after an authentication failure. Rotation may be
observed at the next resolution boundary, while one in-flight request retains
one immutable value. Disable credential-bearing core dumps, centrally redact
errors and telemetry, and fail closed on store outage, authorization failure,
disabled versions, malformed values, excess size, or TLS failure.

The existing `--model-api-key-env` behavior may remain as an explicit local
development compatibility source. It is disabled by default in production
mode, emits a visible warning when enabled, and does not satisfy production
conformance. Secret values are never accepted through a Blueprint, CLI
argument, session API, Cross-VM request, or inline controller profile.

Secret-store configuration and credential bindings are not target capabilities.
`CapabilityManifest` and `EvidenceBundle` omit configured backend kinds,
locations, paths, account/project/vault identifiers, secret versions, and
resolution events. Product release compatibility metadata may declare which
built-in resolver backends are present without revealing deployment
configuration. Runtime-loaded secret resolver plugins are not permitted.

## 16. Likely Interceptor touchpoints

Implementation should prefer small extensions to existing boundaries:

- public schema and strict validation packages;
- session model and persistent attempt registry;
- artifact/spool registration and digest verification;
- injection selector, placement, and application code;
- normalized event and evidence stores;
- feedback projection and cooperative API handlers;
- capability manifest builder;
- native model-proxy codecs, host provider adapters, strict endpoint and
  credential configuration, and provider evidence normalization;
- host credential-reference schema, backend resolver interface, workload
  identity bootstrap, bounded cache, audit redaction, and fake secret stores;
- post-run evidence exporter;
- a narrow authenticated Cross-VM gateway adapter.

Do not put AEF client logic or attack-engine behavior in Interceptor.

## 18. Acceptance criteria

- A non-AEF harness can discover capabilities, register a payload and attempt,
  execute it, receive permitted feedback, and export evidence.
- Operator can execute an AEF-planned scenario without sending AEF-specific
  technique fields to Interceptor.
- Every relevant protected event correlates to attempt and verified payload
  digest where causality is known.
- A black-box engine cannot obtain raw oracle, fixture, canary, event, or
  provider-boundary details.
- A trusted post-run exporter obtains complete or explicitly partial evidence
  after live authority closes.
- Capability manifests are deterministic and secret-free.
- Cross-VM requests cannot acquire Docker, host filesystem, generic proxy,
  shell, arbitrary URL, or private bridge authority.
- Replay, stale revision, mismatched body, expired or revoked lease, excess budget, and
  cross-session operations fail closed.
- Snapshot and restore actions require Operator control, preserve
  content-addressed lineage, enforce local and Operator-held cumulative limits
  across fresh Operator VM revisions, and appear in protected evidence.
- An engine can at most request a permitted snapshot action and cannot obtain
  snapshot bytes, arbitrary inventory, cross-campaign restore, or an
  administrative credential.
- AD-006 and AD-007 tests prove the new ingress positions are distinct from
  existing request-side and model-boundary injection.
- AD-011 tests complete non-streaming text and client-function round trips for
  Anthropic Messages, Gemini Developer API, Vertex Gemini, and Azure OpenAI
  Chat/Responses using only host credentials and like-for-like codecs.
- Unsupported provider/codec pairings, unallowlisted models/deployments,
  caller-selected routing, cross-origin redirects, unknown native fields,
  streaming, embeddings, multimodal content, provider-hosted tools, files, and
  background operations fail before provider contact.
- Each supported secret-store backend resolves an exact allowlisted credential
  using its production workload-identity or Vault auto-auth path without a
  plaintext secret environment variable.
- Caller-supplied locators, unapproved origins, missing or disabled versions,
  malformed or oversized values, integrity failures, and store outages fail
  closed without starting a dependent session or disclosing secret material.
- Rotation is observed only at a defined resolution boundary; protected audit
  records identify the credential binding and opaque backend version without
  storing a locator, value, or unkeyed digest.
- Production mode rejects secret values from environment variables, CLI
  arguments, Blueprints, session APIs, and Cross-VM messages.

## 19. Non-goals

- Generating, adapting, or choosing attack payloads.
- Requiring AEF, Operator, ActionSpec, or MergeRecipe to use Interceptor.
- Exposing all recorded evidence to a live harness.
- Embedding an AEF client or assessment engine.
- Providing arbitrary scripts, callbacks, JSONPath, regex, shell, network
  proxy, host file, or Docker APIs.
- Replacing target-visible behavior with privileged oracle answers.
- Making Cross-VM deployment necessary for simple local open-source use.
- Adding streaming, embeddings, multimodal model content, or provider-hosted
  execution to the first AD-011 slice.
- Creating, updating, rotating, listing, replicating, or administrating secrets
  or secret-store access policy from Interceptor.
- Reimplementing every Vault authentication method inside Interceptor.
